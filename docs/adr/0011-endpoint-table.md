# 端点契约用一张表加一次 sweep 覆盖

端点真正的接口是三元组 (method, path, params)。测试却把它拆成 24 个模块、约 270 个用例，每个方法一份手写的 `assert_called_once_with(GET, PATH, {...})`：95 处断言锁的是内部 params dict，而同一个 dict 已经被候选 01 消掉了重复分支。结果是端点方法一行、测试四行，改一个参数名要同时改两处。

我们决定：**一张表描述全部 279 个端点，一次 sweep 验证它**。表在 `test/unit/okx/endpoints.py`，每行是 (HTTP method, path 常量, 发送的参数名)；`test_endpoint_table.py` 给每个形参喂哨兵值调用一次，比对 method、path、发送的键、发送的值，并把表里的名字与函数签名对照。

表是从运行中的端点面**离线导出一次**、复核后提交的快照，不是每次测试从代码里推导——推导出来的表永远与代码一致，也就永远抓不到漂移。

## Considered Options

- **保留逐方法断言**：覆盖不等于保障。279 个端点里绝大多数没有分支，一份 dict 相等断言与表里一行说的是同一件事，但前者要求读者逐条比对实现。
- **测试时用 `inspect.signature` 生成表**：省掉 279 行维护，但表变成代码的投影：键名拼错、参数漏写都会自动「通过」，因为它描述的就是现状。表的价值恰恰在于它是独立写下的事实。
- **只断言 path、参数交给各模块**：path 面已经由 `test_contract.py` 覆盖；剩下唯一值得收进表的正是参数名，因为那是 01 之后端点方法仅剩的内容。
- **给 279 个端点保留一个「代表用例」**：抽样没有原则——被抽中的端点改错了会红，没抽中的不会。

## Consequences

- 新增端点必须加一行，否则 `test_the_table_covers_every_public_method` 失败；改参数签名必须同步改行，否则 sweep 失败。两处失败都指向具体的 `Class.method`。
- 逐方法用例按「表说不出来的事实」保留：常量字面量、`False` / `0` / `[]` / `''` 的取值语义、位置参数与别名、跨端点参数键对称。共删 113 个用例、约 1350 行。
- 6 个把调用方对象原样转发的端点（`orders_data` / `params`）在表里记为 `PAYLOAD`，不做参数名守护——它们没有名字可拼错，别名与优先级由 `test_trade.py` 覆盖。
- 表与代码一起改错的场景没有第三方校验。这是所有契约测试的共同代价；换来的是端点的任何变更都必须在 diff 里显式出现。
- 与 ADR-0010 的关系：01 让端点方法只说「发什么」，02 让测试只验证「发什么」，两层都不再复述「怎么省略」。
