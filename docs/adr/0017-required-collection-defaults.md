# 必填集合字段用签名默认 `[]` 声明

ADR-0010 把「`None` = 省略」收进 `Transport` 之后，端点上那 14 处 `if x is None: x = []` 全部删除。删完就出现一个新问题：**「这个集合字段必填，调用方不传时要发 `[]`」这句话不能再由 `None` 表达**——`None` 已经被占用成「不发送」。零分支表达它只剩一个位置，签名默认值，于是 14 个形参写成 `x: Any = []`。

这与仓库已记录的决定相反。ADR-0001 把「12 处可变默认参数」列为 0.4.5 修掉的缺陷；`.scratch/sdk-redesign/issues/04-mutable-default-args.md` 的做法是「默认值改 `None`，函数体内按需替换为 `[]`」，完成标准是 `grep -rnE 'def .*=\[\]' okx/` 无输出。当初的理由是共享同一个 list 实例是定时炸弹——即使当下没有调用方就地修改。

`review-2026-11-r2` 的工单 01 拍板 `= []` 时没有按 `docs/agents/domain.md` 的 Flag ADR conflicts 报出这条冲突。评审 `handoff-2026-11-05-review-r2-code-review.md` 的 Standards 轴把它列为该批唯一的硬违规。本文补记这次反转，而不是回退。

我们决定：**必填集合参数用签名默认 `[]` 声明；ADR-0001 里「可变默认参数是缺陷」这一条不再适用于这类参数。**

- **适用范围**：只有「不传就必须发 `[]`」的必填集合字段（当前 14 个形参、分布在 13 行）。其余参数照旧写 `= None`，`None` 仍是「未设置」的唯一值，ADR-0010 不受影响。
- **共享实例为什么可以接受**：这些 list 只被放进新建的 `params` dict，交给 `Transport` 序列化，全仓没有对它们 `append` / `extend` / 下标赋值。风险从「定时炸弹」降为「约定」，本文明写这条约束：**这些默认值不得就地修改**。
- **`None` 哨兵不成立**：ADR-0010 之后 `None` 已经是「省略」，要同时表达「不传 → `[]`」与「显式 `None` → 省略」就得新造哨兵（`MISSING = object()`），并在每个方法体里再加一次分支——正是 ADR-0010 与工单 01 要删掉的东西。

## Considered Options

- **`None` 默认 + 方法体归一化**（`.scratch/sdk-redesign/issues/04` 的老做法）：与 ADR-0010 直接冲突，`None` 会重新有两种解释，14 个分支全部回来。
- **新哨兵 `MISSING`**：语义精确，但把一个内部概念推进 14 个公开签名；`help()` 与文档都要额外解释默认值。
- **`Annotated` 或模块级表**：声明离开签名，下一个人新增同类参数仍要靠记忆去登记，且测试要另写一套读取方式。
- **签名默认 `()`**：`parse_params_to_str` 只对 list/dict 做 JSON 序列化，元组会在 GET 上变成 `%28%29`。

## Consequences

- `.scratch/sdk-redesign/issues/04` 的完成标准作废。现在的守卫换成「默认 list 不被就地修改」，由评审承担，没有自动化。
- ADR-0001 其余结论（0.4.5 只修缺陷、0.5.0 集中破坏性改动）不受影响；被反转的只有可变默认参数这一条。
- 显式传 `None` 与不传从此不同义：`create_rfq(legs=None)` 不再发送 `legs`。这是该批唯一的调用方可见行为变化，已进 CHANGELOG 的 Unreleased。
- 「必填集合字段」目前只由签名默认值表达，没有类型或表结构守住；新增同类参数时，唯一提示是相邻方法的写法。
