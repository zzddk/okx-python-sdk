# 破坏性改动按批次发布

ADR-0001 把 0.4 → 0.5 的破坏性改动集中到了一个版本。0.6 到 0.8 都是非破坏性的特性版本，现在 WS 层需要一次签名变更（删掉死参数、调整回调契约、合并两个重复的类），规则得回答一个问题：是不是每个 minor 都能带破坏性改动？

我们决定：**破坏性改动仍然集中成批发布，每批对应一个以它为主题的 minor 版本**（本批是 0.9.0），不随无关特性或补丁散落。裁量标准是「这批改动是否共享同一个迁移故事」——能写在同一段迁移说明里，就算一批。

## Considered Options

- **永不再破**：等于让 `useServerTime` 这类死参数活到 1.0，代价是每个新读者都要学一遍无用的参数。
- **每个 minor 都允许改**：版本号不再提供任何信号，用户无法判断哪次升级需要读迁移说明。

## Consequences

- 0.9.0 承担 WS 的签名变更，迁移说明要能一段写完。
- 后续若出现小的破坏性需求，先攒着，不要为它单独发一个 minor。
