01 · 把「未设置参数」的规则收回 Transport

Strong
in-process locality

okx/transport.py:107,133,137 · okx/utils.py:51,67 · okx/Trade.py:16-24 · okx/Account.py:12-19 · okx/MarketData.py:11 · 15 个端点 module

Before

端点方法 ×258
同一条规则向上回流
if x is not None: params[x] = x
if x is not None: params[x] = x
if x is not None: params[x] = x
… ×154，分布在 15 个 module
Transport：已经丢弃 None

After

端点方法 ×258
原样传参
Transport：唯一拥有 None 省略
分支删除；规则不再复制

Problem

「None 表示不发送」这条规则由 Transport 拥有，却在 154 处调用点被分支重新实现一次。

Solution

端点方法把全部参数无条件放进 dict，由序列化端唯一决定丢弃；分支全部删除。

Wins

  • locality：规则只活在一处
  • 删除 154 处重复分支
  • 端点 module 的 implementation 退成一行映射
  • 测试只需在 seam 上断言一次
删除测试：删掉分支，复杂度回到 Transport 并集中；不是搬到调用方。ADR-0001 的「None 是唯一未设置值」原样成立。

02 · 把端点测试收成 seam 上的一张表

Worth exploring
in-process leverage

test/unit/okx/test_account.py:1-788 · test/unit/okx/test_funding.py · test/unit/okx/test_trading_data.py · test/unit/okx/test_contract.py:1-154

Before

test_trade
test_funding

24 个 test module · 3280 行 · 95 处 assert_called_once_with

每个方法一份手写 params dict 断言

After

request seam · 一张表

get_positionsGET /account/positions
place_orderPOST /trade/order
get_billsGET /account/bills
… 258 行，同一次 sweep

逐方法测试只留真正有分支的少数

Problem

测试面与 implementation 同宽：断言锁的是内部 params dict，而真正的接口是 (method, path, params) 三元组。

Solution

用一张「方法 → (method, path, 参数名)」的表驱动全部端点；手写用例只保留有条件分支的少数。

Wins

  • leverage：一张表覆盖 258 个端点
  • 参数名拼错在一个 sweep 里暴露
  • 接口收缩成契约表
  • 新增端点只加一行数据
与 01 互补：规则收回 Transport 后，逐方法断言不再锁住冗余分支，这张表才有意义。

03 · 把登录回执收成一个握手

Worth exploring
ports & adapters locality

okx/websocket/WsBaseAsync.py:201-217,220-232,254-291,298-316,325

Before

flowchart LR
  A[consume 读循环] --> B[_handle_message]
  B --> C[_login_waiter]
  D[login] --> E[_read_login_ack]
  E --> F[websocket.recv]
  C --> G[_login_rejection]
  E --> G
  B --> H[_emit]
  E --> H
  classDef leak stroke:#dc2626,stroke-width:2px,color:#dc2626;
  class B,E,H leak

After

flowchart LR
  A[读循环] --> H[LoginHandshake]
  D[login] --> H
  H -->|ack| OK[完成]
  H -->|reject| ERR[ConnectionError]
  H -->|data| EMIT[_emit]
  classDef deep fill:#0f172a,color:#fff,stroke:#0f172a;
  class H deep

Problem

同一次登录应答有两条实现路径；改「什么算拒绝」要改两处，_read_login_ack 还要顺手投递非登录帧。

Solution

一个握手 module 拥有「等哪一帧、什么算拒绝」；读循环与直连 recv 只是它的两个帧来源 adapter。

Wins

  • locality：协议判定只有一处
  • 两个 adapter 共用同一 seam
  • 登录测试不必启动会话
  • 删除 _consuming 这条分支前提
不改 ADR-0005 的串行与异常隔离契约；这是会话内部的一条 seam，不触碰回调接口。

Problem

  • cursor 校验只剩一份

  • 不再反射绑定方法

Problem

Solution
